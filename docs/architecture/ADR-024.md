## Context

The orchestration installer stood up five tooling layers (L1–L5) in one
unratified commit: Superpowers (skills governance), gstack (~57 lifecycle
skills), agency-agents (232 global personas), official plugins
(supabase/sentry/github + marketing/finance/legal/PM packs), and a Ruflo nudge
in the global CLAUDE.md. Costs observed since: >15k tokens of unused agent
descriptions per session (memory: agent-description-token-limit); gstack's
`/ship`//`/commit` flows contradicting house commit conventions (explicit-path
staging, no AI trailer, session finalize-gate); Ruflo used by zero sessions
while its CLAUDE.md nudge contradicts the session system.

## Decision

**Ratified (kept, with duty):**
- **Superpowers** — process skills (brainstorming, TDD, systematic-debugging,
  verification-before-completion, writing-plans) mirror the session chain's
  own discipline.
- **The 9 project `zuka-*` agents** (L3) — lead everything; capsule headers
  per fable-bible 07 §3; a `zuka-flutter` gate is the approved next addition.
- **Official plugins with ZUKA duty:** supabase (+ MCP), sentry (+ MCP),
  github CLI, pr-review-toolkit/code-review, product-management
  (brainstorm/write-spec), ui-ux-pro-max, superpowers, skill-creator, legal
  compliance-check (DPPA passes). Other installed plugin packs remain
  installed but are **out of bounds for ZUKA sessions**; authenticating any
  external plugin MCP from a ZUKA session requires its own ADR.
- **gstack** — remains installed globally, but the following are out of
  bounds for ZUKA sessions (conflict with house process): `/ship`, `/commit`,
  `/land-and-deploy`, `/autoplan`, design/browse/ios suites, codex wrapper.
  The session chain is ZUKA's ship process.
- **agency-agents — TRIMMED 232 → 16.** Keep set (by file):
  `engineering-code-reviewer` · `engineering-backend-architect` ·
  `engineering-database-optimizer` · `engineering-mobile-app-builder` ·
  `engineering-frontend-developer` · `engineering-technical-writer` ·
  `engineering-incident-response-commander` · `security-architect` ·
  `security-appsec-engineer` · `design-ui-designer` · `design-ux-researcher` ·
  `product-manager` · `marketing-growth-hacker` ·
  `support-legal-compliance-checker` · `testing-performance-benchmarker` ·
  `data-privacy-officer` (DPPA duty). Retired agents move to
  `~/.claude/agents_retired_adr024/` (reversible, not deleted). Global
  personas assist; the ZUKA agent always leads (SOUL "most specific layer
  wins").

**Retired:**
- **Ruflo** — zero session usage; its auto-generated block is removed from
  `~/.claude/CLAUDE.md` (backup kept beside the retired agents). Re-adoption
  requires a new ADR stating a duty.

**Enforcement:**
1. Any tooling change (add/remove/upgrade of a layer) ⇒ ADR first — including
   re-runs of `zuka_orchestration_install.sh`, whose header now carries this
   notice; after any reinstall, **re-apply the agent trim** (the installer
   manages `~/.claude/agents/` outside git).
2. The sanctioned menu of record lives in fable-bible
   `07_TOKEN_CONTEXT_GOVERNANCE.md` §4; this ADR ratifies it. Menu edits =
   edit 07 §4 + one-line amendment note here.
3. Sessions may not invoke out-of-bounds skills; reviewers treat it as drift.

## Consequences

- ≈15k tokens returned to every session's working context; agent list becomes
  scannable.
- The double standard closes: the toolchain is now governed by the same
  constitution as the product.
- Reversibility: retired agents/config are moved, not destroyed; other
  (non-ZUKA) projects on this machine lose the retired personas from their
  default listing — acceptable to the founder (same operator), reversible by
  moving files back.
- Residual risk: an installer re-run silently restores the 232; mitigated by
  the header notice + the standing memory item + this ADR's enforcement §1.
