## Chapter 1 — Time Is a First-Class Domain

ZUKA never overwrites meaningful history. Four principles:

```
Temporal Truth          Never overwrite history when it can be preserved
Historical Continuity   History survives device, leadership, platform changes
Data-Led Evolution      Capabilities activate when DATA is ready, not on a date
Immutable Events        All meaningful state transitions are append-only events
```

## Chapter 2 — The Four Clocks

Every entity carries all four timestamps:

```
Reality Clock      (valid_from / valid_to)  When did the real thing happen?
Observation Clock  (observed_at)            When did ZUKA become aware?
Recording Clock    (recorded_at)            When was it written?
Knowledge Clock    (processing fields)      When did downstream systems act?
```

The clocks may differ. A gathering may have happened Friday (Reality), been reported
Saturday (Observation), written Sunday (Recording), and fed a Twin Monday (Knowledge).
All four are preserved.

## Chapter 3 — The Temporal Truth Principle

```
Never overwrite history when history can be preserved.
Every correction appends a new event; the original record remains intact.
The temptation to "clean up" a record is exactly when this discipline
matters most — especially in disputes (Volume 11) and appeals.
```

## Chapter 4 — The DRL Framework (Four Reconciled Ladders, One Gate)

DRL answers: **can a capability EXIST?** One gate, described from four vantage points,
all equivalent:

```
LEVEL  DATA MATURITY      INFRA              DATA USE            INTELLIGENCE
  0    No data            Schemas only        Schemas only        Schemas
  1    Collection         Transactional       Collection          Signal Collection
       FORBIDDEN:                             FORBIDDEN:           FORBIDDEN:
       predictions                            predictions,        trust scoring
                                              trust scoring
  2    Patterns visible   Analytics           Pattern detection   Pattern Detection
  3    Useful insights    Recommendations     Confidence/recs     Explainable Scoring
  4    Automation         Automation          Automation          Trust-Assisted Auto
  5    AI-grade           AI Twins/Copilots   Intelligence        Trust Intelligence
```

The DRL 1 FORBIDDEN list is constitutional: you may collect data at DRL 1, but you may
NOT produce predictions or trust scores from it. That requires DRL 2+ (real patterns).

## Chapter 5 — The Five Assessment Dimensions

Every DRL advancement requires a DataReadinessAssessment across all five dimensions.
All five must independently clear. No weighting, no partial credit, no waivers.

```
VOLUME      domain_event_count + entity_population vs domain minimums
QUALITY     duplicate_rate · broken_relationship_rate ·
            missing_required_fields_rate · clock_order_violation_rate
FRESHNESS   median_data_age · last_event_recency ·
            staleness_risk ('current'|'aging'|'stale'|'frozen')
            A 'frozen' domain CANNOT advance regardless of volume
COVERAGE    geographic_coverage · entity_type_coverage ·
            cold_start_risk — the most frequently blocking dimension
STABILITY   pattern_variance_30d · entity_churn_rate · trend_direction
            A 'declining' domain CANNOT advance regardless of volume
```

Human sign-off is mandatory for every DRL advancement. No automated advancement, ever.

## Chapter 6 — The DRL Activation Contract

No capability activates without a completed nine-section contract:

```
A. Capability identity & target DRL/CRL
B. Required entities, events, signals, relationships
C. Five-dimension assessment results (all must clear)
D. Graph edges touched
E. Founder sign-off (required for DRL 4+, CRL coordinating+,
   financial capabilities, external data consumers)
F. CRL gate confirmation (Volume 07)
G. Provenance check — if ANY field is "No", capability cannot launch (ADR-007)
H. Privacy Impact Assessment reference (if high-risk processing)
I. Fallback & reversal plan
```

## Chapter 7 — Feature Seed Architecture

Every future feature begins as a seed. Even dormant, its required data collection
starts immediately. This eliminates cold-start problems — when the capability's DRL
threshold is finally met, the historical data already exists.

```
A Feature Seed defines:
  Required entities · Required events · Required signals ·
  DRL threshold · CRL threshold · Activation criteria
```
