## Chapter 1 — The Core Thesis

The success of ZUKA depends on transforming deep internal sophistication into extreme
external simplicity.

```
Internally:  Trust OS · Community OS · Opportunity OS · DRL · CRL ·
             Security Systems · Intelligence Systems
Externally:  A simple, intuitive experience.
```

## Chapter 2 — The Experience Constitution

```
LIFE BEFORE FEATURES      Users care about experiences, events, communities,
                          memories, opportunities — not features.
```

## Chapter 6 — The Dashboard Constitution

Every dashboard answers three questions in this order:

```
1. What happened?         (Past)
2. What is happening?      (Present)
3. What should happen next? (Future)
```

```
PERSONAL DASHBOARD   Past: experiences, memories, communities
                     Present: upcoming events, current participation
                     Future: recommendations, opportunities
ORGANIZER DASHBOARD  Past: attendance, revenue, performance
                     Present: active ticket sales, campaigns
                     Future: predictions, recommendations
VENUE DASHBOARD      Occupancy, revenue, peak periods, returning visitors
COMMUNITY DASHBOARD  Participation, trust, continuity, growth (no vanity metrics)
OPPORTUNITY DASHBOARD Connect people with relevant opportunities
```

## Chapter 8 — The Notification Constitution (ZUKA.md §21 + Vol XXII)

Six permitted categories:

```
1. Transactional       ticket, payment, transfer confirmations (non-configurable)
2. Safety-Critical     account security, OTP (non-configurable)
3. Gathering Reminders event starting, doors open, post-event prompt (configurable)
4. Social              tagged in Memory, friend attending (configurable, granular)
5. Discovery           "something near you" (configurable; max 2/day)
6. Anniversary         "on this day" (configurable; grief-sensitive — Volume 10)

TIMING RULES:
  No engagement-optimised timing, ever
  No Categories 3-6 between 10PM-7AM local
  Batch notifications from the same window into one
  Grief/sadness memories: afternoon delivery only (2PM-5PM)
  Max 3 FOMO-type notifications per day
  Unsubscribing from one type never affects others
```

## Chapter 9 — The Anti-Dark-Pattern Constitution

Eight prohibited patterns — no exceptions without founder sign-off:

```
P1 Fabricated Social Proof    no fake "127 people viewing"
P2 Involuntary Social Sharing  no default-on sharing of personal actions
P3 Emotional Manipulation      no using grief/emotion data to manufacture urgency
P4 Consent Dark Patterns       no pre-ticked boxes, no double-negatives
P5 Artificial Scarcity         countdowns only for genuine constraints
P6 Deletion Obstacles          account deletion reachable in ≤ 3 taps
P7 Addiction-Pattern Design    no infinite scroll in Archives; no variable rewards
P8 Pricing Obfuscation         full price (incl. fees) before commitment
```

## Chapter 12 — The Onboarding Flow (ZUKA.md §18)

```
Sign-up is NEVER prompted during passive browsing. Triggered only on first
active engagement (RSVP, Buy, Save, Follow, Tune In, Check In).

Flow (target < 60s):
  1. Phone number
  2. OTP (6-digit, 60s expiry)
  3. First name (required) + last name (optional)
  4. Done — the triggering action completes immediately

Progressive profiling: ask only what's needed, when it's needed.
  First purchase → payment preference
  3rd check-in → category preferences
  5th check-in → neighbourhood pin
```
