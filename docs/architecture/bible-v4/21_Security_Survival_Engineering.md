## Chapter 1 — The Security North Star

Security is not a feature. Security is an ecosystem-wide property. Every capability is
designed for growth, abuse, failure, attack, misuse, insider threats, AND unexpected
success — simultaneously.

```
The platform must become MORE secure as it grows.
Success should strengthen defences, not weaken them.
```

## Chapter 2 — The Security Constitution

```
ZERO TRUST              Never trust by default; verify every request
DEFENSE IN DEPTH        Multiple independent layers
LEAST PRIVILEGE         Minimum access necessary
SECURE BY DEFAULT       Safe configurations out of the box
AUDIT EVERYTHING        Complete trails for every sensitive action
ASSUME BREACH           Design as if the perimeter is already compromised
CONTINUOUS VERIFICATION Every critical assumption tested continuously
```

## Chapter 3 — The Crown Jewels (ranked priority)

The Priority-0 assets, in protection order. This ranking governs where security
investment goes first:

```
1. Identity Graph              Who everyone is — the root of all trust
2. Trust Graph                 Earned confidence — the hardest to rebuild
3. Community Graph             Collective structure
4. Opportunity Graph           Economic value pathways
5. Participation Ledger        The historical record (irreplaceable)
6. Payment Ledger              Financial integrity
7. Historical Memory Archive   Decades of accumulated meaning

These ARE the strategic moat (Volume 06). Protecting them is the first duty of
this volume. If forced to triage during an incident, defend in this order.
```

## Chapter 10 — Application-Specific Protections

```
TICKET SECURITY    Smart Bucket HMAC · rotating QR tokens · contextual-blind
                   scanner binding · offline manifest encryption (Volume 14)
PAYMENT SECURITY   PIN never on Zuka · HMAC signing keys in env secrets ·
                   event-sourced financial ledgers (append-only)
PII PROTECTION     Encrypted at rest · hashed before analytics layer ·
                   k-anonymity (k≥50) before any B2B export
SCANNER SECURITY   RS256 JWT · short-lived sessions · heartbeat revocation
```

---

## Chapter 11 — Data Protection Pipeline (before any B2B export)

```
1. All direct identifiers removed
2. K-anonymity enforced (minimum segment k=50)
3. Differential privacy noise applied to small counts
4. Full audit log of every export (what, when, to whom)
```
