# ZUKA — Concept Document
# V7 Dormant Vision Register

> **Type:** Dormant-vision capture · **Tier:** 3 (parked, not build-now)
> **Status:** Captured & mapped, NOT proposed for build.
> **Authority:** Subordinate to ZukaBibleV4. These are V7 ideas worth preserving
> but premature to build. Each maps to a V4 home and an activation trigger. They
> are the concept-layer mirror of ZukaBibleV4 Vol 24 (the Dormant Register).

---

## Why This Register Exists

The V7 document proposes ~22 operating systems. A handful are genuinely buildable
(captured as Tier 1-2 concepts). The rest are a compelling long-range vision that
would be actively harmful to build now — for a pre-launch, zero-user, solo-founder
product, designing 22 operating systems is the over-planning pattern at its
largest. This register **captures them so nothing is lost**, maps each to where it
would live in V4, and states the observable trigger that would justify reviving it.

```
Captured ≠ committed. Parked ≠ rejected. Mapped ≠ merged.
A vision preserved honestly is more useful than a vision half-built prematurely.
```

## The Register

Each entry: what it is · why dormant now · V4 home · activation trigger.

### Resource OS (knowledge & document generation)
```
WHAT     Turn every ZUKA activity into downloadable reports — financial, legal,
         intelligence, "research-grade thousand-page" documents, an AI report studio.
DORMANT  Needs years of real participation data to generate anything worth reading;
         "thousand-page reports" for a product with no events is absurd. Pure DRL-5+.
V4 HOME  B2B Intelligence products (Vol 23 Ch 8) + the Historian systems (Vol 10/18).
TRIGGER  Multiple domains at DRL 3+; real organisers asking for real reports.
```

### POE — Participation Opportunity Engine
```
WHAT     Match participation demand to economic opportunities (vendors, services,
         jobs) around every event; fair allocation, <40% direct allocation rule.
DORMANT  Opportunity matching needs network density + Trust DRL 2+ (ADR-004).
         Premature exactly as V4's own Opportunity Infra warns (Vol 19).
V4 HOME  Opportunity Infrastructure (Vol 19) — already governs this, already dormant.
TRIGGER  Trust domain DRL 2+; a real density of vendors/services on-platform.
```

### PPN — Participation Partner Network
```
WHAT     A service-provider ecosystem (security, cleaning, medical, transport…)
         with provider identity, capabilities, trust, matching.
DORMANT  A whole two-sided marketplace; vastly beyond MVP. Needs the vendor/
         opportunity layers proven first.
V4 HOME  Opportunity Infra (Vol 19) + Connectors (Vol 20).
TRIGGER  Vendor marketplace live + opportunity matching proven at small scale.
```

### SIOS — Spatial Interaction OS
```
WHAT     Digitally model every physical space (tables, zones, beacons, seats);
         location-aware interactions everywhere.
DORMANT  Heavy infrastructure (BLE/NFC/beacons); the poster + GPS-fence (existing
         concepts) cover the real MVP need for "where are you" far more cheaply.
V4 HOME  Gatherings/hybrid presence (Vol 13) + the Poster concept (zones).
TRIGGER  Venues asking for true indoor wayfinding; poster zones proven and outgrown.
```

### GIE — Gathering Intelligence/Orchestration Engine
```
WHAT     Auto-detect gathering "DNA" and activate capability packs per type
         (wedding/church/funeral/nightclub), gathering "constellations."
DORMANT  The auto-detection is DRL-heavy; at MVP a SIMPLE per-type template
         (the Scanner Pro concept's Layer-2 packs) delivers the value without an engine.
V4 HOME  Gatherings (Vol 13) + the Scanner Pro capability packs (concept).
TRIGGER  Enough events across many types to learn DNA patterns (DRL 2+).
         The capability-PACK idea is usable now; the INTELLIGENCE is dormant.
```

### OIOS — Operations Intelligence OS
```
WHAT     Workforce management, field operations, an "operational advisor"
         ("Gate 2 overloaded → open Gate 3"), real-time ops intelligence.
DORMANT  Real-time operational AI needs live operational data at scale. At MVP,
         the gate-plan suggestion (vendor/gate discussion) + simple staff roles
         cover the real need.
V4 HOME  Testing/resilience ops (Vol 22) + the GatePlan idea (vendor concept).
TRIGGER  Events large enough that manual ops coordination genuinely breaks.
```

### Federation OS
```
WHAT     Orchestrate external ecosystems (ride-hailing, hotels, restaurants) as a
         federation layer; "connect, don't replace."
DORMANT  A grand integration vision; each integration is a connector needing an
         ADR + partner deals ZUKA doesn't have pre-launch.
V4 HOME  Infrastructure & Connectors (Vol 20, ConnectorContract/ADR-013) +
         Dormant (Vol 24). SafeBoda is the one committed connector today.
TRIGGER  Real partner demand + the platform big enough that partners want in.
```

### Vendor Commerce OS (the full V7 version)
```
WHAT     Full catalogs, pricing, inventory, bookings, payments, fulfilment, refunds,
         a "vendor passport" spanning events.
DORMANT  The In-Event Vendor Marketplace CONCEPT (existing, V4-side) is the
         disciplined, NPS-Act-compliant, phased version of this. V7's full commerce
         OS is the far-future end state.
V4 HOME  The In-Event Vendor Marketplace concept (already governs this, phased).
TRIGGER  Vendor marketplace Phases 1-3 shipped and proven; cross-event vendor
         demand real. (The vendor passport ≈ the VendorCompany reputation, later.)
```

### The 18-Month Five-Phase Roadmap
```
WHAT     V7's Phase 1-5 plan building all OSes over 18 months.
DORMANT  ZUKA's real sequencing is V4's readiness-gated, trigger-based model
         (Vol 24) + the session-chain (one task at a time), NOT a fixed 18-month
         all-OS march. A calendar roadmap for 22 OSes is the over-planning trap.
V4 HOME  Scaling & readiness (Vol 24); the session-chain system.
TRIGGER  n/a — superseded by readiness-based sequencing. Kept only as inspiration.
```

### The 28 Principles
```
WHAT     V7's 28 operating principles.
STATUS   ~Half already live in V4 (reality-first, trust-earned, invisible
         sophistication, human enforcement, fair opportunity, participation-first
         — these MATCH V4 and need no action). The genuinely new/sharp ones
         ("one QR is operationally generic", "reality informs not dictates",
         "context fusion over single context", "intent over action", "marketing
         never interferes with operations") are captured in the Tier-1 jewel concept.
ACTION   No new principle doc. Matching principles → already V4. Novel principles
         → folded into the Context Fusion concept. Avoid a rival 28-principle list.
```

## The Discipline This Register Enforces

```
- These are PARKED, not roadmapped. None is "coming"; each is "if/when a trigger fires."
- Each has a V4 HOME so when revived it strengthens the Bible, not a parallel one.
- The over-planning risk is named explicitly: 22 OSes for a zero-user product is
  the exact trap ZUKA must avoid. The vision is inspiring; the scope is not a plan.
- Annual review (like Vol 24's dormant review) re-checks whether any trigger has
  fired. Until then, they wait.
```
